# Code of conduct

## The short version

Be decent. Assume the person you are replying to is trying to help and has less context than you do.
Critique the code, not the person who wrote it.

## In more detail

Examples of behaviour that makes this project better:

- Explaining *why* something is wrong, not only that it is.
- Saying "I do not know" and "I was wrong".
- Asking what a maintainer's constraints are before arguing that they chose badly.
- Writing a bug report somebody else can reproduce.

Examples of behaviour that is not welcome:

- Personal attacks, insults, or dismissing somebody rather than their argument.
- Sexualised language or imagery, and unwelcome attention of any kind.
- Publishing anyone's private information.
- Sustained derailing of a discussion after being asked to stop.

## Scope

This applies in the repository — issues, pull requests, discussions, commit messages — and anywhere
somebody is representing the project.

## Enforcement

Report a problem to the maintainer through a
[private security advisory](https://github.com/jason-te-sde/till/security/advisories/new), which is
the only private channel this repository has. Reports are read by the maintainer and not shared
further without the reporter's agreement.

Responses, in escalating order: a private word, a public correction, having a comment edited or
removed, and being blocked from the repository. Which one depends on severity and on whether it has
happened before.

The maintainer is held to this as well. If the maintainer is the problem, say so publicly in an
issue; there is nobody above them to appeal to, and a public record is the only accountability a
one-person project has.
